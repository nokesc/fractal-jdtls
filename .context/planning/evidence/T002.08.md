# T002.08 evidence: the test scratch folder on disk

Task: [T002.08](../T002.08.md); design §8, "The test scratch folder is on disk, beside the main checkout". Run on the worktree branch `t002-http-endpoint`, 2026-11-08 and 2026-11-09, by the session that did T002.07 (continued on purpose, after a compaction).

## What changed

- **`tests/scratch_folder.py`** (new) is where the scratch folder is, its checks and the lock:
  - **Where:** `<main checkout>__scratch/`. The main checkout is the first entry of `git worktree list --porcelain`, and a bare first entry fails, saying to set the override. `FRACTAL_JDTLS_TEST_SCRATCH` overrides it and must be an absolute path.
  - **Checks, made before anything is created:** a `.git` in the folder or above it (a link counts, even a dangling one); then the folder is made with mode 700 if it's missing; then it must be a folder, owned by the user, and not writable by group or others.
  - **The lock:** `flock(LOCK_EX | LOCK_NB)` on `<scratch>/suite.lock`, opened `O_NOFOLLOW | O_CLOEXEC`. The holder writes its PID, command, working folder and start time into the file. A second run fails at once and quotes them.
  - **Stale pytest locks:** a killed session's `.lock` is removed under the lock, so pytest's pruning isn't held back for three days.
- **`tests/conftest.py`** (new) applies this to every pytest session, unit and integration:
  - In `pytest_configure` it refuses `--basetemp`, prepares the folder and takes the lock. Then it clears stale session locks and sets `PYTEST_DEBUG_TEMPROOT`, so pytest's own numbering and retention run under the folder.
  - The lock's descriptor is never closed, so pytest's pruning at the session's end runs under the lock.
  - A report-header line names the folder, the lock and the holding PID.
  - A session fixture, `session_tmpdir`, sends Python's `tempfile` and the children's `TMPDIR` to the session's own `tmp/`. Gates 1 and 2 showed the need: see the `/tmp` section below.
- **`pyproject.toml`:** `tmp_path_retention_count = 6` and `tmp_path_retention_policy = "all"`.
- **`tests/integration/conftest.py`:** the old `stray_git_above` is replaced by the shared check (`git_at_or_above`, `stray_git_message`). It's still applied to the session's base folder, which covers pytest's own levels under the checked scratch folder.
- **Every other place that assumed `/tmp`:**
  - the comments in `test_imports.py` and `test_run05_fresh.py`, which said "/tmp may be a small RAM-backed tmpfs";
  - `test_integration_harness.py`'s docstring;
  - `AGENTS.md`'s `/tmp/pytest-of-$USER/pytest-current/` text and its "pytest's temporary folder" texts;
  - `tools/pin.py`'s `TemporaryDirectory`, through `session_tmpdir`.

  Literal `/tmp/...` strings that are only arguments, never written to, stay: `test_launcher.py`, `test_install.py`'s tar-member names, `TransportsTest`, and `Fakes.java`'s comment.
- **`.github/workflows/release.yml`:** the gate step now has `id: gate`. When it fails:
  - one step deletes the `pytest-current` links, which only point to the newest session;
  - `actions/upload-artifact@cf430e0… # v7.0.2` uploads `${{ github.workspace }}__scratch/` with `include-hidden-files: true`, for `-data/.metadata/.log`, and is kept for 14 days.
- **`AGENTS.md`:**
  - the test scratch folder, its checks, the lock, the override, retention, and that `--basetemp` is refused;
  - `TMPDIR`, and that JUnit's `@TempDir` and the JVMs' own files stay in `/tmp`;
  - the rule that agents' intermediate data goes in `temp/`, never `/tmp`, and nothing with a `.git` or a `pom.xml` goes there;
  - evidence is self-contained;
  - the `/tmp/.git` trap reworded.
- **`.context/design.md` §8:** one `[REVIEW HERE]` with T002.08's details (see "Decisions for review").
- **Tests:** `tests/unit/test_scratch_folder.py`, 19 tests.
  - Where the folder is: the first entry, the sibling of a linked worktree, a bare repository's worktree, the override, a relative path refused, and outside any repository.
  - The checks: made with mode 700; refused for modes 777, 772, 702, 770 and 720; a `.git` inside, above (a file) or as a dangling link; a file; a link checked where it leads.
  - The lock: a second holder refused with the PID; after `kill -9` the lock is free; it isn't inherited by a child that keeps its descriptors.
  - Stale session locks cleared.
  - Nested pytest sessions with the suite's configuration: seven sessions keep six plus `pytest-current`; a held lock and `--basetemp` each exit 4.
  - Temporary files go to the session's folder, in-process and in a child.

## Decisions for review

These are in design §8, behind the one `[REVIEW HERE]` ("T002.08's details").

1. **pytest's names, through `PYTEST_DEBUG_TEMPROOT`.**
   - The sessions are `<scratch>/pytest-of-<user>/pytest-<n>/`, and the task's "`current` link" is pytest's own `pytest-current`.
   - pytest documents that variable as the override of its temporary root (`pytest --help`: "Override the system temporary directory"). Anything else would need its private APIs, or `--basetemp`, which the task rules out.
   - `suite.lock` sits above `pytest-of-<user>/`, outside what pytest prunes.
2. **"Not writable by others" is read as group or others (`go-w`).**
   - The suite makes the folder with mode 700. A folder made by hand under the usual umask 002 is 775 and is refused, with the `chmod` to run.
   - The other reading, others only, would accept a folder a shared group can write.
3. **A killed run's pytest `.lock` is removed under the suite's lock.**
   - pytest won't prune a session whose `.lock` is under three days old (`LOCK_TIMEOUT`), and `kill -9` leaves it behind. Retention would then keep seven sessions for three days.
   - While the suite holds the `flock`, no other session can be using that `.lock`, so removing it is safe.
4. **`--basetemp` is refused, and the override must be absolute.** Both fail loudly rather than emptying a folder or resolving against whatever the working folder is.
5. **The lock's descriptor is close-on-exec and never closed.**
   - A JDT LS the run started can't keep the lock, even if it outlives the run.
   - pytest's pruning at the session's end still runs under the lock.
6. **Python's temporary files and `TMPDIR` go to the session's `tmp/`.**
   - Gates 1 and 2 show `tools/pin.py`'s tests writing to `/tmp`. Fixing it once for every session, rather than passing `--cache-dir`, which means a persistent cache, also covers children such as `git` and Python tools.
   - Java ignores `TMPDIR`, and `java.io.tmpdir` stays out of scope.
