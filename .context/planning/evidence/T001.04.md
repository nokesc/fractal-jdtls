Maven used the scratch repository `/tmp/fractal-jdtls-t001/m2/repository` through `MAVEN_ARGS`. ## What was built

- **The boot jar**, `org.fractal.jdtls.boot`. This is the helper the advice calls. It uses JDK types only in its signatures, and reaches m2e and Maven by reflection.
  - `Boot`: naming, the per-thread requester (nested-safe) and the resolution rule. It is the spike's `fix` behavior, always on. `getProjectFacade` looks candidates up with an `ArtifactKey`, not by scanning the map. An unexpected failure inside a hook is reported once, and m2e's result is kept.
  - `Worktrees`: the nearest ancestor containing `.git` (a file or a folder) is the worktree. Its folder name is the prefix. A prefix collision is reported once per colliding worktree.
  - `Hooks`: the in-place state of each hook, the checkpoint (the first return from `populateClasspath`) and the shutdown check.
  - `Report`: loud failures, written to stderr and to the JDT LS log.
    - The JDT LS log is reached through `Platform.getLog` via a bundle class loader. Reports found during a class transformation are queued, and flushed from the next advised call, the checkpoint or shutdown.
    - Stderr is the process's own file descriptor 2. JDT LS replaces `System.err` after it starts (see "A defect found and fixed").
  - `DiagnosticLog`: off by default. It is enabled with `-Dfractal.jdtls.diagnosticLog=<file>`, and writes one JSON line per event.
    - Events: `agent-start`, `hook-in-place`, `hook-not-in-place`, `transform-error`, `checkpoint`, `shutdown`, `naming`, `lookup`, `prefix-collision` and `hook-failed`.
    - A `lookup` event is logged for every lookup that has at least one workspace candidate. (Changed in review R2: now for every call.)
- **The agent jar**, `org.fractal.jdtls.agent`.
  - `Hook` is the table of the six hooks in design §6, and no others. Each matcher names the full parameter list by type name.
  - `Installer` counts the declared methods each matcher selects as the class loads. It advises only when exactly one is selected, and marks the hook in place only once the class has transformed.
  - `Advices` holds the inlined advice.
  - `Agent.premain` checks that Byte Buddy and the boot helper can be loaded, and otherwise fails with a message naming the missing file.
  - The manifest from T001.01 is kept as it was: `Premain-Class`, `Boot-Class-Path: fractal-jdtls-boot.jar`, `Class-Path: byte-buddy-1.18.14.jar`. Byte Buddy is not bundled.
- **The test-only broken-hook agent:** `BrokenHookAgent` (test sources). It is built as `agent/agent/target/fractal-jdtls-agent-broken-hook.jar`, a test-jar with its own manifest, and is never in the zip. Its agent argument names the hook whose matcher becomes `named("<id>ThatDoesNotExist")`.
- **Tests.**
  - JUnit 6.1.3: 31 boot tests and 5 agent tests, run by `mise run build`.
    - Worktree detection: a `.git` folder, a `.git` file, no `.git`, the nearest ancestor.
    - Naming, including a project outside any worktree being left unchanged.
    - The collision report.
    - Requester selection: `context.pom`, `populateClasspath`, nested Maven parents, per-thread.
    - The resolution rule.
    - Checkpoint and shutdown reporting.
    - The hook-in-place rule: zero or two selected methods of a small test class are reported.
    - The six-hook table.
  - `tests/unit/test_byte_buddy_version.py` now also checks the built agent jar's manifest.
- **`mise.toml`:** `test` now depends on `build`, so the jar test always has a built jar. Within `validate`, mise runs `build` once (see item 5). AGENTS.md is updated to match.

### A defect found and fixed

The first pass of run 04 put the report in `.metadata/.log` but **not on stderr**. The getProjectFacade report in run 03 did reach stderr.

- **Cause:** JDT LS's `LanguageServerApplication` calls `System.setErr` once it has started, as `javap -c` shows. It sets either a file stream or a `ByteArrayOutputStream`. So any report made after that through `System.err` is lost. `DefaultModelBuilder` loads after that point; m2e core loads before it.
- **Fix:** `Report` now writes to the process's own stderr, `new FileOutputStream(FileDescriptor.err)`. The tests capture reports through a package-private field, or through the diagnostic log.
- The first pass's stderr, from `/tmp/fractal-jdtls-t001/t004/evidence/04-broken-maven/lsp.stderr` before the fix, was the five JDK/Byte Buddy warning lines and nothing from the agent. After the fix, every run in this file was redone from a fresh install.

## For Chris

- **Byte Buddy's `sun.misc.Unsafe` warning.** Byte Buddy 1.18.14 prints a 4-line deprecation warning on Java 25 at every start, from `ClassInjector$UsingUnsafe`. It's harmless now, but later JDKs plan to make these methods throw. Byte Buddy's `net.bytebuddy.safe` property, or a later Byte Buddy, may avoid it. I didn't change either: that's a pin decision.
- **The stock launcher writes into the install when run directly.** It writes `eclipse/bin/__pycache__` unless Python runs with `-B` (item 2). T001.05's launcher doesn't run `eclipse/bin/jdtls`, so it shouldn't hit this, but it's worth knowing for the "nothing is written inside the install" check.
- **The diagnostic log property** is `fractal.jdtls.diagnosticLog`. Design §6 now names it (commit 69dbd05).
- **Unexpected failures inside a hook** are reported once per hook, and m2e's own result is kept. An example is a reflective field renamed in an m2e update. The design names hook-not-in-place and transform errors; this is the same "fail loudly" rule applied at runtime, without breaking m2e.
- **The test-only broken-hook jar** comes from `mise run build` (the agent POM's `test-jar` execution), so T001.06 can reuse it.

## Review

Cross-agent review `.context/planning/T001.04_agent_review.md` (not committed). Every finding was checked against the code and fixed.

- **R1, fixed.** The "already prefixed" guard came from the spike. It made distinct artifact IDs such as `harness-app` and `wt-a.harness-app` collide in one worktree.
  - Design §6, as settled in 69dbd05, says m2e's name is always prefixed. `getProjectName` is called only from `create()`, and m2e computes its name afresh from the POM, so no real path hands it an already-prefixed name. `Boot.projectName` now always prefixes inside a worktree.
