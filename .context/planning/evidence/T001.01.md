# T001.01 evidence: repository skeleton and release gate

Recorded 2026-11-01 on branch `t001-first-release`, Linux (WSL2), mise 2026.9.5.

**How the fresh clone was tested.** A fresh clone needs a commit, so the work was committed first (`225a273`), cloned into the scratch root and checked there; this evidence file was then added to that same commit with `git commit --amend`. The amend changes only this file, so the tested tree is the committed work.

**Maven local repository.** Every Maven run here used a scratch local repository under `/tmp/fractal-jdtls-t001/`, through `MAVEN_ARGS=-Dmaven.repo.local=…`; `~/.m2` was not used. The `build` task itself runs plain `mvn`, which uses `~/.m2` as design §8 allows for the agent build.

**Failures along the way.** No check failed. One slip, not a check failure: the first `mkdir`/`cp` ran from `.context/planning/` (a leftover `cd`), so `LICENSE`, `.agents/`, `.claude/` and empty folders landed there; they were moved to the root before any check ran.

## Notes for review

- **Layout choices the design leaves open:** the Maven modules are `agent/agent/` (artifact `fractal-jdtls-agent`) and `agent/boot/` (`fractal-jdtls-boot`); the jars build to `agent/*/target/fractal-jdtls-{agent,boot}.jar`, without versions in their names. The root POM's version is `0-dev`: the release ID comes only from `pin.json` (design §2).
- **The agent manifest is already in place** (`Premain-Class`, `Boot-Class-Path: fractal-jdtls-boot.jar`, `Class-Path: byte-buddy-${byte-buddy.version}.jar`, `Can-Retransform-Classes`), so the POM property is the only place the version appears. The `premain` is an empty stub.
- `pyproject.toml` names the project `fractal-jdtls` with no runtime dependencies; pytest is in the `dev` dependency group, which `uv sync --locked` installs.
- Maven plugin versions are pinned in the root POM's `pluginManagement` (latest 3.x on Central as of today), and `project.build.outputTimestamp` is fixed so the jars are reproducible.
