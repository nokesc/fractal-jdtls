## Review

The cross-agent review (`.context/planning/T002.12_agent_review.md`) found two problems, both in the README's HTTP startup example. The governor's notes asked for both to be fixed there and the example kept short. Nothing else changed.

- **R1 (a stale port file could be read): fixed.** The example waited for `$XDG_RUNTIME_DIR/jdtls-port.json`. The launcher removes a port file left from an earlier run only after its checks, so a file a crashed run left behind could be read first. Each launch now uses a fresh path, in a new folder made by `mktemp -d`, so no earlier file can ever be at that path.
- **R2 (a failed start waited forever): fixed.** The example now:
  - records `$!` (the launcher replaces itself with JDT LS's `java`, so that's the process to stop);
  - sets a 120 s deadline;
  - checks on every pass of its loop that the process is still running.

  If the process ends first, the example says so and stops. If the deadline passes, it stops only that recorded PID, and says which. "The port file" bullet now says the same: the start failed if the file is late or the process ends first.
- **The release notes** show only the launch command, with no wait for the port file, so they carry nothing to fix.

The new example in the README:

```bash
port_file="$(mktemp -d "${XDG_RUNTIME_DIR:-/tmp}/jdtls.XXXXXX")/port.json"  # a fresh path per launch: never a stale file
jdtls -data ~/.cache/my-tool/jdtls-workspace --http-port-file "$port_file" --http-settings settings.json &
pid=$!  # the launcher becomes JDT LS's java, so this is the process to stop
deadline=$((SECONDS + 120))
until [ -e "$port_file" ]; do
  kill -0 "$pid" 2>/dev/null || { echo "jdtls (PID $pid) exited before listening" >&2; exit 1; }
  [ "$SECONDS" -lt "$deadline" ] || { echo "no port file after 120 s: stopping PID $pid" >&2; kill "$pid"; exit 1; }
  sleep 0.2
done
```
