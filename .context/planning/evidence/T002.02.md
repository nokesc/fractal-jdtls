  | Proposal | Where in §11 |

  | 2, process lifetime | "Inside JDT LS": `-DwatchParentProcess=false` from the launcher, `processId: null`. |

  The governor's five decisions from `cb92460` are unchanged. "The refresh scope … comes back for review in T002.02" and "Whether reads of one worktree must wait while another worktree imports is measured in T002.01 and T002.09" are gone; "Readiness" now says any import holds requests, as "Imports run alone" decided. The measurements (machine, loading times, sync and refresh costs, complete-operation latencies, cancellation, worktree add and remove times) are quoted where each mechanism is described. A new subsection, "Constraints and risks", carries the pinned internals, the silent broken imports, the mtime limit, refresh cost, in-process hangs, and what's not yet measured. §10's line about runtime folders now says T002.01 tested them.
- **Four `[REVIEW HERE]` proposals** change §11's meaning, for the governor to settle. The governor approved all four in `2811cc1`, and replaced their markers (see "Review of the description" below):
  1. **The refresh scope is the worktree, for queries too** (from HTTP-FINDINGS "Recommendations"). A module-only refresh misses changes in the modules a query depends on or that depend on it.
  2. **What `changedPaths` does:** with the worktree as the scope there's nothing to narrow, so named files are taken in even if their mtime didn't change, and the request never takes the fast path.
  3. **`build` versus `problems`, with autobuild off:** every fixed point that refreshes builds, so `problems` takes the fast path when it can, and `build` never does, with an optional `clean`.
  4. **The passthrough sends requests only,** and also refuses `workspace/didChangeConfiguration` and five project-changing `workspace/executeCommand` commands.
- **The contract,** `endpoint/src/main/resources/openapi.json` (OpenAPI 3.1, 10,364 lines): 23 operations, the shared `worktree` and `module` fields, the `Sync` report, `JavaName` and `TextAnchor` with their syntax written for an LLM, and the error catalogue (`ErrorCode`, 39 codes, each with `x-status`, `x-retryable`, `x-candidates`, when it happens and what to do, and an example problem `error-<code>` in `components.examples`). ### The walkthrough

T002's overall loop (start in HTTP mode, add two worktrees, edit a file on disk and `build`, rename a method by name with a clean build, remove a worktree, shut down), as the requests and responses the description defines, with the three error cases: an unregistered worktree (step 5), an ambiguous member (step 6) and text that isn't unique (step 8). Each request and response below is one of the description's own examples (the loop's steps are its examples for those operations, and the error responses its catalogue's `error-<code>` examples), so the validation test has checked every one against its schema. The fixture is the integration fixture with the spike's `Names.java` and `Greeter.java` (T002.06 grows it so), as a main checkout and linked worktrees `/work/wt-a` and `/work/wt-b`.

## Decisions for review

My own choices in the contract, which need no `[REVIEW HERE]` because they don't change §11's meaning:

1. **Operation names and paths:** the 23 above. Navigation operations sit directly under `/v1/`, refactorings under `/v1/refactor/`, and `outline` (one file) is apart from `symbols` (a search of the worktree). `describe` is "the signature and Javadoc of a named element".
2. **`target`** is a Java name (a string) or a text anchor (an object), one field for both. Anchors get an optional **`select`**, the part of `text` the operation acts on (which must occur once in `text`), so `text` can be long enough to be unique while the operation acts on one name inside it. `within` is §11's "once within a named member".
3. **Candidates** are `{"set": {<JSON Pointer>: <value>, …}, "about": "…"}`. One candidate can set several fields at once (`file-in-other-module` sets `module` and the file), and a candidate is always applied the same way. A problem's `field` names the field that failed. `text-not-unique` also lists `occurrences`, and offers candidates only where `within` tells them apart.
4. **Error codes beyond §11's eight,** with their HTTP statuses: the 39 above. Not-found for things named in the request is 404, ambiguity and inapplicable requests are 422, state conflicts are 409, waiting is 503, and timeouts are 504.
5. **`type`** is `urn:fractal-jdtls:error:<code>`: an RFC 9457 type URI needn't resolve, and the description is the reference.
6. **Defaults:**
   - `timeoutMs` is 120,000 for queries and `lsp`, 300,000 for `build` and refactorings, and 900,000 for worktree adds and removes. The maximum is 3,600,000, and `/v1/status?wait=ready` defaults to 120,000.
   - Problems default to `severities: ["error"]`. `limit` is 200 for problems, references and implementations, and 50 for symbols.
   - Hierarchies default to `depth` 10 for types and 1 for calls.
7. **Running out of time while still waiting** for JDT LS or an import is `not-ready` (retryable, with `retryAfter`). `timeout` is only for work that started and was cancelled, with its `phase`.
8. **Adding a registered worktree again** is harmless (`added: false`), and waits for its import if one runs, so `wait: false` followed by a second add with `wait: true` is the way to wait. **Removing an unregistered worktree** is `worktree-not-registered`, loudly, not a silent no-op.
9. **A rename starts from the declaring module** (`declared-in-other-module`, whose candidate names it), because §11's rename scope is the requesting module and its dependents. `references` and `implementations` keep §11's scope literally, from the requesting module.
10. ~~**Names address the worktree's own sources** (proposal 11's scope), so a library or JDK element is reached through a text anchor.~~ **Replaced by the governor in `2811cc1`:** read-only operations fall back to the requesting module's classpath (above).
11. **Positions and paths:**
    - Columns are 1-based and count characters, and `endColumn` is just after the range. A source line is cut at 500 characters.
    - Files in requests and results are relative to their module, while `sync` and diff paths are relative to the worktree.
    - Worktree paths are resolved through symbolic links.
12. **Requests are strict.** Unknown fields are `invalid-request`, which catches an LLM's misspelled field instead of ignoring it. Clients ignore unknown response fields.
13. **Request bodies are limited to 1 MiB** (`request-too-large`). **`status`, `openapi.json` and `shutdown` never answer `busy`,** and `shutdown` called again answers `202` again.
14. **Extract operations:**
    - `name` is required, and arrives in the same edit (as the governor decided for extract method in T002.07).
    - `replaceAll` defaults to `false` for a variable and `true` for a constant, as in Eclipse's dialogs.
    - Organize imports takes `choices` for ambiguous simple names, and answers `ambiguous-import` otherwise.
15. **`text-not-found` offers a candidate** when the text occurs with different whitespace, carrying the file's exact text.
16. **The SPDX line in a JSON file:** JSON has no comments, so the description's first key is the extension `"x-license": "SPDX-License-Identifier: Apache-2.0"`, and `info.license.identifier` is `Apache-2.0`. The licensing test doesn't check `.json` files; this follows the rule anyway.
17. **Details I added inside the governor-marked bullets, with no marker of their own:**

    - a settings file that sets a fixed setting otherwise is refused at startup, not overridden (proposal 8);
