## What was built

**`tests/integration/`** is the integration suite (design §8). It is a port of the spike's `lsp_driver.py`, `make-fixture.sh`, `run-all.sh` and `fixture/`.

- **`fixture/`** is the spike's fixture, moved with `git mv`. Its POMs stay `pom.xml.fixture`. I added SPDX lines, and the parent POM's comment now names the suite instead of the spike's script.
- **`scenario.py`** holds the shared steps:
  - `make_worktrees` replaces `make-fixture.sh`. It builds a scratch main checkout and two linked worktrees at one commit, renaming `pom.xml.fixture` only in those copies. Git runs without the user's or the system's configuration.
  - `JdtlsRun` replaces the driver. Everything it needs is passed in: the command, the worktrees, `-data`, the Maven `settings.xml` and the run folder. It runs `initialize` (with `java.configuration.maven.userSettings`), then import, edits and reimport, exactly as the spike did. Snapshots are taken from `java.project.getAll`, `java.project.getClasspaths`, error diagnostics and the workspace's project metadata. After `ServiceReady` it also records `/proc/<pid>/cmdline` and `exe`.
  - `DiagnosticLog` reads the agent's log.
- **`lsp_client.py`** is the spike's minimal LSP client. If JDT LS exits, a waiting request fails instead of hanging. The suite stops only the process it started, by its recorded PID.
- **`conftest.py`** does the once-per-session setup:
  - It fails, naming the folder, if a `.git` sits above pytest's temporary folder.
  - It builds the release zip with `tools/release_zip.py` from the jars of `mise run build`, unzips it, and installs it with the zip's own `install.py --root <scratch>/release/root`. That downloads the JDT LS tarball and Byte Buddy.
  - It sets up the persistent Maven cache: `$FRACTAL_JDTLS_TEST_CACHE`, else `.cache/integration/` in the checkout, which is git-ignored.
  - It gives JDT LS's JVM an empty scratch `user.home` and the launcher a scratch `XDG_CACHE_HOME`.
- **`test_worktrees.py`** has three module-scoped runs and seven tests. Each run launches through the installed `bin/jdtls` with exactly what a client passes: `--jvm-arg=-Dfractal.jdtls.diagnosticLog=<run>/agent.jsonl`, `--jvm-arg=-Duser.home=<scratch>` and an explicit `-data`. It passes no agent, boot delegation or `-configuration`.
  - **Run 05:** import, edits and reimport on fresh worktrees.
  - **Run 06:** a new process on run 05's `-data` and worktrees.
  - **Run 01, the control:** fresh worktrees, through `launch_without_agent.py`.
  - The tests also check that Maven used only the suite's repository, and that the install still verifies afterwards.
- **`launch_without_agent.py`** is the test-only launch path. It loads the installed `bin/jdtls` without writing bytecode and calls its `prepare()`, which verifies the install and builds the command a client would get. It then removes the two agent arguments, failing if they've changed, and execs `java`. It isn't in the release zip.
- **`mise.toml`:**
  - the new task `test:integration` depends on `build` and runs `python -m pytest tests/integration`;
  - `validate` is now `test`, `release:zip`, then `test:integration`;
  - `pyproject.toml`'s `testpaths` stays `tests/unit`, so `mise run test` is still the unit tests only.
- **Retiring the seed:**
  - `FINDINGS.md` moved, with `git mv`, to `.context/research/jdtls-worktree-spike.md`. It has a new preface that links the Notion spike page (from the seed's README), explains what became of the spike's code and the agent modes used in the runs table, and describes the fixture. Its reference to the deleted `scripts/run-all.sh` and its evidence path are reworded. The findings themselves are unchanged.
  - `.context/spike/` is deleted.
  - Links are updated in `.context/design.md` (line 5), `.context/planning/T001.md`, `.context/planning/T001.04.md` and `AGENTS.md`.
- **Docs:**
  - `AGENTS.md` describes `tests/integration/`, `mise run test:integration` and its network and cache needs, the new `validate`, and `.context/research/`.
  - `README.md` has a "Known gaps" section: adding and removing workspace folders at runtime is untested (design §10), and the agent must be present on every start (design §6 asks for that to be documented for users).

## For Chris

- **The stray `/tmp/.git`** comes from another project's Codex sandbox (`bwrap --bind /tmp /tmp`). Whenever that session is active, it can fail the agent's two JUnit tests and the whole integration suite; both fail with a message naming it, as the governor asked. Rerunning in a quiet moment passed. A lasting fix is outside this repository: for example, Codex's writable roots could leave out `/tmp`, or point `TMPDIR` elsewhere for that session.
- **Where the suite's persistent Maven cache lives.** The default is `.cache/integration/` in the checkout, which is git-ignored, and `$FRACTAL_JDTLS_TEST_CACHE` overrides it. That choice is mine; design §8 asks only for "a scratch cache that persists between runs".
- **JDT LS gets an empty scratch `user.home`** (`--jvm-arg=-Duser.home=…`) on top of `java.configuration.maven.userSettings`. That lets the suite show, in a test, that Maven never fell back to a default repository, and keeps `~/.m2` out of reach. It's a client-side JVM option; the product doesn't change.
- **Every session downloads the JDT LS tarball** (about 53 MB) by running the zip's own `install.py`, as a user would. Design §8 allows caching the tarball by its SHA-256, but `install.py` has no cache option, so I didn't add one. If CI time matters, that's a possible later change.
- The README gained a "Known gaps" section. It covers runtime workspace-folder changes (design §10, as the task asked) and the agent being needed on every start (design §6 asks for that to be documented for users).

- **R1, fixed.** `wait_quiet` could return at once for the edits and reimport steps, because the quiet left over from the step before still counted. Run 05's own timeline showed the risk: the import had been quiet since 12.09 s, the edits were sent at about 20.6 s, and the step waited only because a `$/progress` at 20.60 s happened to arrive before the first check.
  - `wait_quiet` now takes `since`, a `time.monotonic()` taken before the step's notifications are sent. The server must then show activity after `since`, followed by `quiet` seconds of nothing. If there's no activity at all, the error says so ("had no activity").
  - `edits()` and `reimport()` pass `since`. The import's wait, which has none, is unchanged.
  - The check now polls every 0.05 s when `quiet` is under a second, which only affects the unit tests.
- **R2, fixed.** File URIs were cut down to paths without decoding percent escapes, and diagnostics were matched by comparing a plain path against an encoded URI.
  - `scenario.py` has new functions: `local_path` (it decodes `file:` URIs, as `file:/` or `file:///`, and keeps plain paths), `relative`, and `error_diagnostics` (it matches documents by their decoded path).
  - Snapshots now use them for projects, classpath entries, workspace locations and diagnostics.
- **R3, fixed.** `maven_settings` escapes the repository path with `xml.sax.saxutils.escape`, and writes UTF-8 with an XML declaration.
