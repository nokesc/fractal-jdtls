# T002.04 — Worktrees and modules

Step 4 of [T002](T002.md).

## Why now

Every later operation names a worktree and module, and depends on the mapping and checks this task builds.

## Depends on

T002.03.

## Design

- [design.md](../design.md) §11: "The contract" (the mapping checks), "Worktrees"; §6 (worktree identity) and §10.
- [HTTP-FINDINGS](../research/jdtls-http-spike.md), question 4.

## Changes

- **`worktrees/add`, `/remove` and `/list`,** as in the approved description:
  - waiting for the import, or `not-ready` with `retryAfter`;
  - adding is refused for a folder that isn't a Git worktree root, and for a folder name already in use;
  - removing deletes the worktree's Eclipse projects without deleting their files, and cleans m2e's registry;
  - a worktree already deleted from disk can still be removed;
  - listing returns modules with their path, GAV and import state.
- **The mapping from `worktree` and `module` to an Eclipse project,** with every check in §11 "The contract", each failure a catalogued problem with a `hint`. A small internal operation that only maps and checks may back the tests, if the description lists it.
- **Integration tests through HTTP only:**
  - start with no worktrees;
  - add `main`, `wt-a` and `wt-b`;
  - check names and resolution through `list`, and through the agent's diagnostic log, as in run 05: every lookup has a requester and stays in its worktree;
  - remove one worktree, then remove one that was deleted from disk;
  - restart, then add the same worktrees again;
  - each refusal and each mapping error.

## Acceptance

Record real output for each item.

- **Runtime adds:** the three worktrees import, with run 05's names and the diagnostic log's per-worktree resolution.
- **Removal:** the removed worktree's Eclipse projects are gone and its files are untouched (show a file hash before and after). A later lookup's candidates, in the diagnostic log, don't include its POMs.
- **Each mapping error,** with its problem body shown:
  - a worktree that isn't registered;
  - a module path without a `pom.xml`;
  - a module that hasn't been imported yet;
  - a module that the agent placed in another worktree. Reproduce it with a nested `.git` inside a module folder, the shape of the stray `/tmp/.git`.
- **Each refusal,** with its problem body shown: a duplicate folder name, and a folder that isn't a worktree.
- `mise run validate` passes.

## Out of scope

- Reconciling with the disk, builds and problems (T002.05).
