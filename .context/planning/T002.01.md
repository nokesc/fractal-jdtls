## Questions

Questions 1 to 4 are **blocking**: if one fails and there's no alternative within design §11, stop with `T002.01-BLOCKED.md`. Report what failed, the alternatives and a recommendation.

1. **Loading.** How does our bundle load and start before any LSP client exists?
   - Try the candidates in §11 "Inside JDT LS", and record which work.
   - The chosen way must keep the install read-only: `install.py --verify` passes after a run, and nothing is written inside the install.
2. **The in-JVM client.**
   - The bundle connects to JDT LS as its only client, with no TCP socket or pipe that another process could open. Show what's listening (`ss -ltnpx`) for the JVM.
   - It sends `initialize` with no workspace folders and with settings from a file, including `java.configuration.maven.userSettings`.
   - JDT LS stays up when stdin is closed, and ignores parent process IDs.
   - It answers JDT LS's requests back to the client.
3. **HTTP in OSGi.** `com.sun.net.httpserver` is usable from the bundle under Equinox. Record what that needs, for example boot delegation (which the launcher already merges, §5) or system packages.
4. **Worktrees at runtime.**
   - Start with no folders, then add `main` and `wt-a` with `didChangeWorkspaceFolders`. Show that the agent's naming and resolution are as in run 05: the diagnostic log shows every lookup with a requester, and every final choice in its own worktree.
   - Add `wt-b` while `wt-a` is busy, and remove `wt-a`. Show that:
     - its Eclipse projects are deleted;
     - its files are untouched;
     - m2e's registry no longer offers its POMs as candidates (a later lookup's candidate list, in the diagnostic log).
   - Remove a worktree that was already deleted from disk (`git worktree remove --force`).
   - Restart with the remaining folders: names and classpaths are kept, as in run 06.
5. **Deterministic disk sync.**
   - Write run 05's edits to disk without telling JDT LS. Reconcile with `refreshLocal`, send changed POMs through m2e's project update, and join the build jobs. Then read the markers. The errors must equal run 05's.
   - Repeat 20 times on a fresh copy: the results are identical every time.
   - Also detect a `git checkout` of another commit, and a POM change that adds a dependency.
   - Compare autobuild on (join) with autobuild off (explicit incremental build), and recommend one.
   - Measure `refreshLocal` cost on a module and on a whole worktree, for the fixture and for a generated tree of about 50 modules and 10,000 Java files (generated in scratch, POMs never committed).
6. **Threading.**
   - Measure how long a read on `main` (`textDocument/definition`, `workspace/symbol`) takes while `wt-b` imports, and while a full build runs.
   - Show that `$/cancelRequest` and a cancelled progress monitor stop a long operation.
   - Record which JDT LS operations take the workspace rule.
7. **A refactoring end to end.**
   - `textDocument/rename` of a method used across modules gives a `WorkspaceEdit`. Apply it with the spike's own writer, then refresh, build and show a clean build.
   - One code-action refactoring (extract method) run non-interactively, through `java/getRefactorEdit` or the equivalent, with its choices given as arguments.
8. **Names.** Resolve `org.fractal.harness.contract.<Type>#<member>(<params>)` with JDT's `SearchEngine`, scoped to one worktree's projects. Show that the same type in another worktree isn't returned, and how overloads are distinguished.
