# T002.06 — Navigation and search by name

Step 6 of [T002](T002.md).

## Why now

Refactorings address code the same way, so names and text anchors must work first. Navigation is also what an LLM uses to understand code before changing it.

## Depends on

T002.05.

## Design

- [design.md](../design.md) §11: "Addressing code", "Navigation and search", "Errors", and the contract's rule that results never cross worktrees.
- [HTTP-FINDINGS](../research/jdtls-http-spike.md), question 8.

## Changes

- **Resolving Java names** (types, nested types, members, overloads, fields, packages) and **text anchors** (file plus exact text, optionally within a member), scoped to the requesting module and the worktree modules that depend on it.
  - An ambiguous name is `ambiguous-member` or `ambiguous-type`, with every candidate written so it can be passed back.
  - Text found nowhere is `text-not-found`, with the closest matches.
  - Text found more than once is `text-not-unique`, with each occurrence's line.
  - **Library and JDK names** resolve through the requesting module's classpath for the read-only operations, as a second scope (§11 "How names resolve"). Test one JDK member (`java.lang.String#join`) and one Maven dependency's type.
- **The navigation operations in the description:** definition, references, implementations, type hierarchy, call hierarchy, file and worktree symbols, and Javadoc with the signature.
  - Each runs through JDT LS's LSP handlers where they exist, or through JDT directly where that's what the spike recommended.
  - Answers are in the caller's terms: Java names, files relative to their module, and 1-based lines with the source line.
- **The fixture grows Java sources** for these tests: overloads, a nested type, an interface with two implementations, and a call chain across `harness-contract` and `harness-app`. Its POMs stay `pom.xml.fixture`. The T001 integration suite's expected diagnostics are updated only if the new sources change them, with the reason recorded.
- **Integration tests through HTTP only,** across `main`, `wt-a` and `wt-b`:
  - every operation;
  - every addressing error;
  - a type present in all three worktrees, which is returned only for the worktree that asks.

## Acceptance

Record real output for each item.

- **Each operation's answer** for one fixture element, in the evidence.
- **No crossing:** references to a contract type, requested from `wt-a`, list only `wt-a` files, and the same request from `main` lists only `main` files.
- **Each addressing error,** with its problem body shown. An LLM reading only the problem could correct its request. Show the corrected request succeeding.
- `mise run validate` passes.

## Out of scope

- Changing code (T002.07).
