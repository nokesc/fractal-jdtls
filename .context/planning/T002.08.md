# T002.08 — The LSP passthrough

Step 8 of [T002](T002.md).

## Why now

It reaches everything JDT LS offers that the curated operations don't cover yet, so Harness isn't blocked waiting for later series.

## Depends on

T002.05 (reconciling with the disk). Placed after the curated operations, so they come first.

## Design

[design.md](../design.md) §11, "The LSP passthrough".

## Changes

- **`POST /v1/lsp`:**
  - takes `worktree`, `module`, `method` and `params`;
  - reconciles with the disk first;
  - sends the request to JDT LS unchanged, with the same timeout and cancellation as every operation;
  - wraps a JDT LS error as `lsp-error`, keeping the raw error.
- **Refused methods,** with a catalogued problem naming the operation to use instead:
  - lifecycle methods;
  - workspace folder changes;
  - document synchronization;
  - anything else that would break the endpoint's ownership of the connection.
- **A `WorkspaceEdit` the passthrough returns** isn't applied. If JDT LS sends `workspace/applyEdit` during a passthrough request (for example from `workspace/executeCommand`), the endpoint answers "not applied", and says so in the response. This is documented in the description.
- **Integration tests:**
  - `textDocument/documentSymbol` and `workspace/executeCommand` `java.project.getClasspaths`, which reproduce one of run 05's classpath checks;
  - each refused method;
  - a JDT LS error.

## Acceptance

Record real output for each item.

- **Two passthrough requests,** with their real responses.
- **Each refused method,** with its problem body shown.
- **An `lsp-error`,** with the raw error kept.
- `mise run validate` passes.

## Out of scope

- Filtering passthrough results by worktree (§11).
