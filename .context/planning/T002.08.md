# T002.08 — The test scratch folder on disk

Step 8 of [T002](T002.md). Inserted by the governor on 2026-11-08, at Chris's request.

## Why now

`/tmp` is a tmpfs held in memory, and every gate puts its fixture worktrees, scratch installs, `-data` folders and the large tree there. That RAM is taken from the JDT LS heaps, Maven and the agents. `/tmp` filled up during this series, and the laptop's restart wiped the records of earlier runs. T002.11's soak would make it worse, so this comes before every remaining gate.

## Depends on

Nothing new. The suite as T002.07 left it.

## Design

[design.md](../design.md) §8, "The test scratch folder is on disk, beside the main checkout".

## Changes

- **Every pytest run, unit and integration, gets its base folder under the scratch folder:**
  - `<main checkout>__scratch/`, the main checkout found from `git worktree list --porcelain` (so this worktree uses the main checkout's sibling); a layout with no main checkout fails, saying to set the override;
  - `FRACTAL_JDTLS_TEST_SCRATCH` overrides it;
  - checked before anything is made or pruned: owned by the user, not writable by others, no `.git` in it or above it;
  - pytest's own numbered sessions and retention (not `--basetemp`, which empties its folder), the latest six kept (three gates of two sessions), and a `current` link to the newest.
- **A kernel lock (`flock`) for the whole run,** on a lock file at the scratch folder's top, outside the pruned runs: a second suite run while one holds it fails at once, naming the holder's PID. Show it, and show that a run killed with `kill -9` leaves nothing that blocks the next.
- **The `.git`-above check stays,** now applied to the scratch folder. Its message says what to do if the scratch folder is ever inside a checkout.
- **Nothing in the suite assumes `/tmp`.** Find every place that does (tests, conftest, helpers, the evidence instructions in AGENTS.md) and move it. JUnit's `@TempDir` folders are small and may stay in `/tmp`; say so in AGENTS.md.
- **Evidence stays self-contained:** run folders are pruned, so evidence keeps copying the output it cites.
- **The release workflow** uploads the scratch folder as an artifact when the gate fails (check it with actionlint, as AGENTS.md says).
- **AGENTS.md:** where the scratch folder is, the lock, the override, and the rule that agents' other intermediate data goes in the checkout's git-ignored `temp/`, never `/tmp`, and nothing with a `.git` or a `pom.xml` in it. Replace the `/tmp/pytest-of-$USER/pytest-current/` text.

## Acceptance

Record real output for each item.

- **A full `mise run validate`,** with:
  - `/tmp`'s use (`df -h /tmp`, and `du -sh` of anything the gate wrote there) before and after: it doesn't grow by the suite's scratch;
  - the run's folder under the scratch folder, listed;
  - the wall time compared with T002.07's gate (5:42).
- **The lock refusing a second run,** with its message.
- **The `.git`-above check** still failing with a stray `.git` above a scratch folder given through `FRACTAL_JDTLS_TEST_SCRATCH` (in a scratch location, removed afterwards).
- **Retention:** after seven sessions of a small subset, six numbered folders and `current`.
- **The scratch folder's checks:** refused when writable by others, and when a `.git` is inside it.
