# T002.05 — Disk sync, builds and problems

Step 5 of [T002](T002.md).

## Why now

This is the loop an LLM uses most: edit, build, read the errors. Every later operation reconciles with the disk the same way first.

## Depends on

T002.04.

## Design

- [design.md](../design.md) §11: "Keeping in step with the disk", "Builds and problems".
- [HTTP-FINDINGS](../research/jdtls-http-spike.md), question 5; FINDINGS run 07; T001.06 review finding R1.

## Changes

- **Reconciling with the disk,** as the spike chose and Chris approved:
  - refresh the scope;
  - send changed POMs through m2e's project update;
  - join the build, or build explicitly;
  - the optional `changedPaths` narrows the refresh;
  - the `sync` report.

  One implementation, used by every operation that depends on code.
- **`build` and `problems`,** as in the description. Problems come from markers, filtered by severity, with 1-based positions and the source line.
- **Retire the seed:**
  - port anything still needed from `.context/spike/http/`, then delete it;
  - keep HTTP-FINDINGS, fixing its links;
  - remove or justify any test-only switch that T002.01 added.
- **Integration tests through HTTP only,** with files changed on disk and never reported:
  - run 05's edits: `build` in each worktree returns run 05's errors;
  - a `git checkout` of another commit;
  - a POM change that adds a dependency;
  - a file deleted on disk.

## Acceptance

Record real output for each item.

- **Run 05 through `build`:** wt-a reports the 3 `WorkType cannot be resolved` errors, wt-b only its own `Broken.java` error, and main none.
- **The same result every time:** the run 05 scenario repeated 20 times, each on a fresh copy, gives identical problems, with the summary in the evidence.
- **Detected without being reported:** the `git checkout`, the POM change and the deletion each show up in the next `build`, and in its `sync` report.
- **The cost:** `sync` timings for the fixture, and for the spike's generated tree of about 50 modules and 10,000 files. If a worktree refresh takes more than a second, record it and raise it with Chris (§11).
- `git grep -n "spike/http"` finds no remaining links to the deleted seed.
- `mise run validate` passes.
