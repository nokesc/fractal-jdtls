# T001.07 — Release

Step 7 of [T001](T001.md). Always last.

## Why now

The release is what consumers, starting with Fractal Harness, pin.

## Depends on

Every earlier T001 task.

## Design

[design.md](../design.md) §2 (releases) and §9 (releasing).

## Changes

- **`.github/workflows/release.yml`**, as in §9: on a pushed `v*` tag, it:
  1. fails unless the tag is `v` plus `pin.json`'s `release`, then builds;
  2. runs `mise run validate`;
  3. creates a draft release for the tag;
  4. attaches the zip;
  5. publishes.
- **README usage,** for anyone:
  - prerequisites (Linux, Python 3.10+, a JDK at the pin's minimum);
  - downloading a release and running `install.py`;
  - putting `bin/jdtls` on `PATH` or pointing a client at it;
  - the agent's "fresh `-data`" rule;
  - known gaps;
  - how to report a problem.
- **Release notes** for `v1.63.0-1`: what's pinned, and which files are trusted only through Eclipse's checksum.

## Acceptance

Record real output for each item.

- **A local dry run of the workflow's steps:** the tag check, for both a matching tag and a mismatched one, then build, `mise run validate`, and the zip. Show the zip's file list.
- **Install from that zip** into a scratch root, then launch through `bin/jdtls`.
- The workflow file passes `actionlint`, or a review with the reason if `actionlint` isn't available.
- **For Chris:** the exact tag command, and the repository setting for immutable releases. The agent doesn't tag, push or publish.

## Out of scope

- Artifact attestations, and any platform other than Linux.
