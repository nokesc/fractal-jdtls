# T001.05 — The launcher

Step 5 of [T001](T001.md).

## Why now

Every client, and the integration suite, starts JDT LS through it.

## Depends on

T001.03 and T001.04.

## Design

- [design.md](../design.md) §5.
- The stock launcher, `bin/jdtls.py`, in the installed Eclipse tarball.

## Changes

- **`bin/jdtls`**, exactly as in §5:
  - the stock command line, plus the agent and boot delegation;
  - Java detection and the minimum-version check;
  - default `-data` keyed on the canonical full path;
  - a writable `-configuration` outside the install;
  - verification of the install at launch;
  - replacing itself with the `java` process.
- **Unit tests:**
  - the exact `java` command line for representative arguments;
  - Java detection order, and a rejected old JDK;
  - default `-data` for two folders with the same name;
  - a launch refused when the install fails verification.

## Acceptance

Record real output for each item.

- **A real launch** through `bin/jdtls` from a scratch install answers LSP `initialize` for a scratch Maven project. The agent's transformed-target lines appear.
- **After that run,** `install.py --verify` passes. Nothing was written inside the install; show the check.
- **The verification cost** at launch, measured. If it's more than about 0.5 s, raise it with Chris.
- **Too-old Java:** a launch with `--java-executable` pointing at a JDK below the minimum fails with the minimum named. If no such JDK is available, show the unit test's output instead.
- `mise run validate` passes.

## Out of scope

- Any client conventions, such as compiler preferences, LSP settings or JVM sizing (design §1).
