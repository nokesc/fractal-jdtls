# T001.04 — The agent

Step 4 of [T001](T001.md).

## Why now

The launcher always adds the agent, so the agent must exist first.

## Depends on

T001.01. A JDT LS install from T001.03, to check that the hooks transform.

## Design

- [design.md](../design.md) §6.
- The spike's [FINDINGS.md](../spike/jdtls-worktree-spike/FINDINGS.md), "Result" and "Constraints and risks".
- The spike's sources, in `../spike/jdtls-worktree-spike/agent/`.

## Changes

- **Port `Spike.java` and `SpikeAgent.java`** into `org.fractal.jdtls.boot` and `org.fractal.jdtls.agent`, with the spike's `fix` behavior always on. Remove the modes, `spike.worktrees` and `spike.mavenRequester`.
- **The two jars,** as in §6: the agent jar names Byte Buddy with `Class-Path` and the boot jar with `Boot-Class-Path`. Byte Buddy is not bundled.
- **Loud failures:**
  - a hook target that wasn't transformed, or failed to transform;
  - a prefix collision between two worktrees, reported once.
- **An optional diagnostic log,** off by default.
- **Unit tests** for the parts that don't need JDT LS: worktree detection, naming, the collision report, and requester selection.

## Acceptance

Record real output for each item.

- **Byte Buddy loads through `Class-Path`.** A JVM started with only `-javaagent:<lib>/fractal-jdtls-agent.jar`, and Byte Buddy beside it, runs `premain` without `NoClassDefFoundError`. Removing Byte Buddy from `lib/` produces a clear failure.
- **Under the real JDT LS 1.63.0 install,** started by hand with the agent, the log shows every hook target from FINDINGS transformed, and no transform errors. Use the spike's driver from the seed, or a minimal LSP `initialize`.
- `mise run validate` passes.

## Out of scope

- The launcher (T001.05) and the full scenario suite (T001.06).
