# T001.03 — The installer

Step 3 of [T001](T001.md).

## Why now

The launcher and the integration suite run from a real install.

## Depends on

T001.02.

## Design

[design.md](../design.md) §2 (releases and layout) and §4 (installing).

## Changes

- **`bin/install.py`**, exactly as in §4:
  - standard library only, Python 3.10 or newer;
  - installs the release it ships in into `<root>/<release>/`, with a default root that a flag or an environment variable overrides;
  - idempotent and atomic;
  - Byte Buddy into `lib/`;
  - `--verify`;
  - clear errors and non-zero exits.
- **A `release:zip` Mise task** that builds the release zip in the §2 layout into `build/`. It includes the jars from `mise run build`. T001.07 makes it the release artifact; it's needed earlier for testing.
- **Unit tests** against a fake download server and a scratch root:
  - a tampered tarball;
  - a tampered unpacked file;
  - a tampered Byte Buddy jar;
  - an interrupted install (no partial target remains);
  - a second run that does nothing;
  - `--verify` naming missing, extra and changed files.

## Acceptance

Record real output for each item.

- **A real install** from the built zip into a scratch root succeeds. A second run reports there's nothing to do. `--verify` passes.
- **After a tampering edit** to one file in the scratch install, `--verify` names that file and exits non-zero.
- No file outside the scratch root and the system temp folder was written. Show how you checked.
- `mise run validate` passes.

## Out of scope

- Launching JDT LS (T001.05).
