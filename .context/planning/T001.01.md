# T001.01 — Repository skeleton and release gate

Step 1 of [T001](T001.md).

## Why now

Every later task is accepted against this gate and runs in this toolchain.

## Depends on

Nothing.

## Design

- The Fractal conventions, in `CONVENTIONS.md` in the umbrella repository (`~/github/nokesc/fractal/`): "Starting a new Fractal project", "Toolchain: mise" and "Agents".
- [design.md](../design.md) §7 (licensing) and §8 (testing and the gate).

## Changes

- **Starter files from the conventions:**
  - `mise.toml`, with Python, uv, Java `25.0.1` and Maven `3.9.12` at the Fractal base versions, and workmux;
  - `pyproject.toml` and `uv.lock`, with pytest as a development dependency. The shipped scripts stay standard-library only;
  - `scripts/bootstrap.sh`;
  - `.gitignore`. It also ignores Eclipse metadata (`.project`, `.classpath`, `.settings/`, `.factorypath`) at any depth, because JDT LS runs on this checkout too;
  - `.agents/skills/`, and the committed link `.claude/skills -> ../.agents/skills`.
- **`AGENTS.md`**, in the conventions' four sections:
  - what the project is;
  - the structure: `bin/`, `agent/`, `tools/`, `tests/`, `.context/`;
  - the hard rules: design §1, plus no IDE-importable fixture POMs;
  - the commands.
- **Licensing:** `LICENSE` (Apache-2.0), `NOTICE`, and SPDX headers in the files this task creates.
- **Build layout for the agent:** a Maven build from the repository root that produces the agent jar and the boot jar. It compiles against Byte Buddy, which it doesn't bundle, at the version in the root POM's `byte-buddy.version` property: `1.18.14`, the version the spike ran (design §3). That property is the only place the version is chosen. For now it builds empty stubs; T001.04 fills them in.
- **Mise tasks:**
  - `setup`;
  - `test` (unit tests);
  - `build` (the jars);
  - `validate` (the full gate: for now `test` and `build`; later tasks add the zip and the integration suite).

## Acceptance

Record real output for each item.

- `./scripts/bootstrap.sh` passes from a fresh clone of this branch, into a scratch folder.
- `mise tasks ls` lists every task, each with a description.
- `mise run validate` passes, including one placeholder unit test.
- `git status --ignored` shows Eclipse metadata ignored once JDT LS has opened the checkout, or a `.project` created by hand.

## Out of scope

- Any installer, launcher or agent behavior.
- Adding this project to the umbrella repository's README. Chris does that.
