**Request changes: S1, S2 and S4 are resolved; S3 and S5 still need tighter guarantees.**

- **S1 — resolved.** `writeSetDigest` now binds exact bytes, paths, existence and promised metadata effects; comparison includes recomputed no-ops.
- **S2 — resolved.** Private, hashed backups under `-data` remove Git-object retention and durability dependencies; unresolved backups cannot be evicted.
- **S3 — partly resolved:** atomic publication, rename intermediate states and journaled creation address the main failures. Still require restored files and affected directories to be synced **before deleting the rollback journal**, and sync parent directories when publishing journal directories. Preserve owner/group or refuse before mutation—the conditional ownership preservation in [point 4](/home/nokes/github/nokesc/fractal-jdtls__worktrees/t002-http-endpoint/temp/governor/T002/opfolders-v3-proposal.md:22) permits silent ownership changes. Also block subsequent applies immediately after a live rollback or completion-recording failure leaves an unresolved journal.
- **S4 — resolved.** Durable source completion precedes reconciliation, and later failures retain an explicit applied result.
- **S5 — partly resolved:** immutable baseline comparison and model-generation validation address the main gaps. Extend fail-closed scanning beyond **recorded paths** to all relevant discovery/traversal/stat failures, including the baseline scan. Otherwise an unreadable new directory can hide inputs without changing the file map; today [FileRecords.visitFileFailed](/home/nokes/github/nokesc/fractal-jdtls__worktrees/t002-http-endpoint/endpoint/src/main/java/org/fractal/jdtls/endpoint/FileRecords.java:90) silently continues.

- **T1 — Major — Startup recovery needs external-writer serialization too.** Point 3 requires Harness to serialize writers during applies, but point 4 automatically writes during startup recovery. An agent can change a file after recovery validates it and before rollback replaces it, losing that newer change. **Fix:** extend Harness serialization to startup recovery, from before process launch until recovery finishes; require the same exclusion during manual resolution. Without that exclusion, retain the journal and require coordinated recovery.
- **T2 — Moderate — Successful journals have no cleanup rule.** The proposal deletes rolled-back or manually resolved journals, but startup skips journals marked “sources done,” and successful applies never explicitly remove them. Repeated refactorings could retain unlimited original-file backups and exhaust `-data`. **Fix:** delete completed journals once source completion is durable and their request handling has finished; clean remaining completed journals at startup. Preserve every unresolved journal.

Over-built: retaining completed journals would duplicate Git/Harness history; publication folders and transient recovery journals remain justified.
